# ipplan — IPv4 子网规划工具

`ipplan` 读取一个 JSON 规划任务（地址池、保留网段、子网申请），确定性地
生成互不冲突的子网分配方案，并报告每个池的剩余空间与地址总量统计。

工具只做离线计算，**不会修改任何网卡或系统网络配置**；仅使用 Go 标准库。

## 运行

```sh
go run ./cmd/ipplan -in task.json -out plan.json
# 或位置参数：
go run ./cmd/ipplan task.json plan.json
```

- 成功：退出码 `0`，方案写入 `-out` 文件。
- 失败：退出码非零，输出文件写入错误对象（见下），**不会输出部分成功的方案**。

## 输入格式

所有网段均为 IPv4 CIDR，前缀长度为 `0..32` 的整数，且必须是网络地址
（主机位非零会被拒绝，不会自动截断）。`/32` 表示单地址申请。

```json
{
  "pools": [
    { "id": "office", "cidr": "10.10.0.0/22" }
  ],
  "reservations": [
    { "id": "gw", "pool": "office", "cidr": "10.10.0.0/24" }
  ],
  "requests": [
    { "id": "svc-a", "pool": "office", "prefix": 24 }
  ]
}
```

- `pools`：地址池。池之间不得重叠；池 `id` 全局唯一。
- `reservations`：保留网段。`pool` 必须指向某个池；网段必须**完整属于**
  该池；同一池内保留网段不得重复或重叠；`id` 全局唯一。
- `requests`：子网申请。`prefix` 为所需前缀长度（`0..32`）；`pool` 必须
  指向已存在的池；`id` 全局唯一。

三类编号各自唯一；输入数组的先后次序不影响结果。

## 分配顺序

在每个池内部：

1. 申请按**前缀长度从小到大**处理（先满足大块，避免被小块切碎）。
2. 前缀长度相同时，按申请 `id` 的**字典序**处理。

每次为当前申请选择**地址最小、且按该前缀对齐**的完整空闲网段；该网段
不得跨越任何保留网段或已分配网段。已完成的分配不会为后续申请挪动
（无重排、无压缩）。

地址按整段空间计数，**不扣除网络地址与广播地址**（例如 `/30` 计 4 个地址，
`/32` 计 1 个地址）。若任一申请无法满足，整个规划失败。

## 输出格式（成功）

```json
{
  "allocations": [
    {
      "request": "svc-a",
      "pool": "office",
      "cidr": "10.10.1.0/24",
      "start": "10.10.1.0",
      "end": "10.10.1.255"
    }
  ],
  "pools": [
    {
      "pool": "office",
      "cidr": "10.10.0.0/22",
      "remaining": ["10.10.2.0/23"]
    }
  ],
  "statistics": {
    "total": 1024,
    "reserved": 256,
    "allocated": 256,
    "remaining": 512
  }
}
```

- `allocations`：每个申请分配到的网段及首末地址，按申请 `id` 排序。
- `pools[].remaining`：该池剩余空间的**数量最少**、互不重叠的 CIDR 集合，
  按网络地址升序排列；剩余空间**不会跨池合并**。无剩余时为 `[]`。
- `statistics`：地址数量统计，恒满足
  `total = reserved + allocated + remaining`。

所有区间运算使用 `uint64` 整数按整段完成，支持 `0.0.0.0/0` 这类大地址池
  （共 2³² 个地址），不逐地址展开，输出规模只与网段数量相关。

## 输出格式（失败）

```json
{
  "error": {
    "object": "pool | reservation | request | task",
    "id": "出错对象的编号",
    "reason": "人类可读的原因"
  }
}
```

典型失败：CIDR 主机位非零、池互相重叠、保留网段越界或重叠、申请引用了
不存在的池、编号重复、池内没有足够大的对齐空闲网段。

## 测试

```sh
go test ./...
```

测试覆盖：前缀长度/字典序分配顺序、保留网段造成的碎片空间与最少 CIDR
聚合、`/32` 单地址、`0.0.0.0/0` 大池的守恒统计、输入次序无关性，以及
各类校验与"无法满足即整体失败"的场景。
