# IPv4 Subnet Planner (ipplan)

从地址池与保留网段生成不冲突的 IPv4 子网分配方案，并以最简 CIDR 集合报告各池剩余空间。仅使用 Go 标准库，不修改网卡或系统配置。

## 运行

```sh
go run ./cmd/ipplan <task.json> <plan.json>
```

成功时退出码为 0，方案写入 `<plan.json>`；任一申请无法满足或输入非法时退出码非 0，标准错误输出定位到具体对象的 JSON 错误，且不写出部分成功的方案文件。

## 输入格式

```json
{
  "pools":    [{"id": "p1", "cidr": "10.0.0.0/8"}],
  "reserved": [{"id": "r1", "pool": "p1", "cidr": "10.1.0.0/16"}],
  "requests": [{"id": "a1", "pool": "p1", "prefix": 24}]
}
```

- 三类对象（池、保留网段、申请）的 `id` 各自唯一。
- 所有网段为 IPv4 CIDR，前缀 0–32，必须使用网络地址；主机位非零会被拒绝而不是自动截断。
- 池之间互不重叠；保留网段必须完整属于其 `pool`，同一池内保留网段不得重复或重叠。
- 申请通过 `pool` 指定所属池，`prefix` 指定所需前缀长度（`/32` 表示单地址）。

## 分配顺序与规则

1. 在每个池内，先按前缀长度从小到大（`/25` 先于 `/26`）处理申请；同长度按申请编号字典序处理。
2. 每次选择地址最小、且按该前缀对齐的完整空闲网段；分配不能跨过保留或已分配区域，已分配网段不会被搬动。
3. 按整段地址空间分配，不扣除网络地址与广播地址。
4. 任一申请无法满足（例如碎片空间中没有足够大的对齐空闲块）则整个规划失败，错误信息指出该申请及原因。
5. 输入 JSON 中对象的排列次序不影响结果。

## 输出格式

```json
{
  "allocations": [{"request": "a1", "pool": "p1", "cidr": "10.0.0.0/24",
                   "start": "10.0.0.0", "end": "10.0.0.255"}],
  "pools": [{"id": "p1", "remaining": [{"cidr": "10.0.1.0/24",
             "start": "10.0.1.0", "end": "10.0.1.255"}]}],
  "stats": {"total": 16777216, "reserved": 65536, "allocated": 256, "remaining": 16711680}
}
```

- `allocations` 按处理顺序给出每个申请的网段与起止地址。
- 每个池的 `remaining` 是数量最少且互不重叠的 CIDR 集合，按网络地址排序，不跨池合并。
- `stats` 统计总量、保留量、分配量、剩余量（地址个数），满足 `total = reserved + allocated + remaining`；统计基于区间运算，支持 `0.0.0.0/0` 等大地址池，不逐地址展开。
